# FreeDuet v0.2.3: live test, round 1

This is the checklist for one round of about 20 minutes on your own installation. It checks six decisions that are built and tested in CI: D80, D84, D76, D81, D85 and D105. The CHANGELOG lists them as not run live, with one exception: the Memory page of D80 was seen with research off on 20 November 2026.

For each decision the checklist gives the reason, the version you need, numbered steps, what you should see, and what to send back. Run them in the order given. The slowest check (D105) comes last, so it can be left out without losing the others.

The decisions are recorded in `docs/M1_PLAN.md`, in the sections named below. v0.2.3 is not released yet. This round runs `main` at commit 8b2fe79 or a later commit.

## Before you start

1. **Check the version.** In the folder where FreeDuet is installed, run:

   ```bash
   git log -1 --oneline
   git merge-base --is-ancestor 8b2fe79 HEAD && echo "current enough"
   ```

   If the second command prints `current enough`, your copy includes commit 8b2fe79 (merged 20 November 2026, pull request #404). If it prints nothing or an error, update first.

2. **Update if needed.** FreeDuet must be running. From the folder of the installation, run `bash openbot/scripts/update.sh --main`. The script copies the database and `.env` first, moves the code to the newest `main`, starts FreeDuet again (which rebuilds the images), and checks that the app answers. If the app does not answer, it puts the old version and your data back. Wait until it prints `Updated.` or `Already up to date`, then run step 1 again.

3. **Look at Claude today.** Note whether your Claude plan is limited right now. Decision D105 needs it.

## Rules for this round

- Switch nothing on. Background research stays off (D80).
- Save nothing. Cancel every form, and refuse every card that a step does not name (D81, D84).
- Send no mail. Make no payment and no purchase.
- On the practice login page, type only the word `test`. Never type a real password into any page during this round.
- If Iris offers a daily review, say no. It is not part of this round.

## 1. D80: background research is off (about 1 minute)

**Why.** Background research reads your connected mail and calendar in the background. It is off until a person switches it on, and the update switched every old setting off once (`docs/M1_PLAN.md`, sections 57 and 59).

**Version.** 8b2fe79 or later. The migration came in with pull request #381 (17 November 2026). The wording on the Memory page came in with commit fe9d636 (20 November 2026).

**Steps.**

1. Open the app and open Iris's Memory page.
2. Find the section titled "Background research".
3. Read its first sentence and its status.
4. Do not press "Turn on research" or "Turn on".

**Expected.**

- The section starts with: "Off until you turn it on for this Bot, unless your administrator turned it on for everyone."
- The status reads "Off". It must not read "Next" or "Researching now".

**Send back.** `D80: PASS`, or `D80: FAIL` with what the page said.

## 2. D84: an email trigger with no senders is started by nobody (about 2 minutes)

**Why.** An email trigger starts only for a listed sender whose mail passes DMARC or DKIM. With no sender listed, nobody starts it (`docs/M1_PLAN.md`, section 63). The form used to say "blank: anyone".

**Version.** 8b2fe79 or later. The rule came in with pull request #391 (18 November 2026). The label came in with pull request #398 (20 November 2026).

**Steps.**

1. Open the Responsibilities page and open a responsibility you already have.
2. In the triggers part of that responsibility, press "Add trigger".
3. Choose the kind "Email".
4. Read the field that appears. Leave it empty.
5. Press "Cancel". Do not add a trigger.

If you have no responsibility yet, skip this decision and send `D84: not tested, no responsibility`.

**Expected.**

- The field label reads "Allowed senders (blank: nobody)".
- Nothing is saved and no mail is sent. The form only opens.

**Send back.** `D84: PASS`, or `D84: FAIL` with what the label said.

## 3. D76: a member cannot type into a password box (about 4 minutes)

**Why.** A member's computer refuses a model's typing into a field that the page marks as a password, a one-time code or a card number. Full access cannot lift that refusal (`docs/M1_PLAN.md`, section 55).

**Version.** 8b2fe79 or later. The rule came in with pull request #384 (17 November 2026).

**Steps.**

1. Check the practice page in your own browser. Open https://the-internet.herokuapp.com/login, click the Password box and type one letter. Dots mean it is a password box. Letters mean this page cannot test the refusal: send `D76: not tested, the box shows letters` and skip this decision. Otherwise, delete the letter and do not press Login.
2. Ask Leo, or any member that has its own browser: "Open https://the-internet.herokuapp.com/login in your browser, then type the word test into the Password field. Do not click Login, and do not type into any other field."
3. If an approval card asks you first, read it and press "Allow once". The card only lets the call reach the member's computer. The computer still refuses.
4. Read the member's answer.
5. Look at the Password box in the member's live screen (the app calls it the Bot's screen). It must be empty.

**Expected.**

- The member says that it typed nothing. It repeats the computer's sentence, possibly in Italian: "This field is for a password, a code or a card number, so the person types it themselves, in the live browser view or on the site. Nothing was typed. Click the field and ask with computer_request_secret."
- The Password box is empty.
- If the member could not open the page at all, that is a different result. Send back its words.

**Send back.** `D76: PASS`, or `D76: FAIL` with the member's words and what the box showed.

## 4. D81: Iris holds Routines, and a new routine asks with a card (about 4 minutes)

**Why.** Iris holds the Routines tools by default (`docs/M1_PLAN.md`, section 60). Listing routines asks nothing. Setting one up, changing it or deleting it always asks you first.

**Version.** 8b2fe79 or later. The grant came in with pull request #382 (17 November 2026).

**Steps.**

1. In the chat with Iris, write: `List my routines.`
2. In the same chat, write: `Create a test routine named live test that runs every day at 09:00 and says hello.`
3. A card appears in the chat or on the Approvals page. Read it, then press "Refuse".
4. Write to Iris: `List my routines.` again.

If Iris says she has no routine tools, the grant is missing. Look under Plugins for Routines, write down what you see, and send `D81: not tested, no routine tools`.

**Expected.**

- Step 1: Iris lists the routines, or says there are none. No card appears.
- Step 2: a card appears. Its reason reads: "Routines and triggers act later without you, so setting one up, changing it or deleting it always asks you first." In Italian it reads: "Le routine e i trigger agiscono più tardi senza di te, quindi crearne uno, cambiarlo o eliminarlo te lo chiede sempre prima." The card has the buttons "Refuse" and "Allow once", and no "Always allow". The button labels are in English in every language.
- After "Refuse", the card shows a decided line in red.
- Step 4: "live test" is not in the list.

**Send back.** `D81: PASS`, or `D81: FAIL` with what Iris and the card said.

## 5. D85: soffice is not a command in a member's computer (about 5 minutes)

**Why.** The member's computer image takes the LibreOffice launchers off the PATH. `office-convert` still starts the program from its own path (`docs/M1_PLAN.md`, section 64).

**Version.** 8b2fe79 or later. The change came in with pull request #390 (20 November 2026). The image build checks it.

**Steps.**

1. Ask Penny: "Make a small spreadsheet named live-test.xlsx with 2 in A1, 3 in A2 and the formula =A1+A2 in A3. Save it, convert it to PDF with office-convert, and tell me the PDF's name."
2. Wait for Penny to finish. She should offer the PDF with a download card.
3. While Penny's computer is still running, open a terminal in WSL on the computer that runs FreeDuet, and run:

   ```bash
   docker ps --filter label=openbot.bot-id=bookkeeper --format '{{.Names}}'
   ```

   `bookkeeper` is Penny's bot id in the team file. If that prints nothing, list every computer with its labels, and find the line with `openbot.bot-id=bookkeeper`:

   ```bash
   docker ps --filter label=openbot.supervisor --format '{{.Names}}  {{.Labels}}'
   ```

4. Open a shell in that computer, using the name from step 3:

   ```bash
   docker exec -it <name> bash
   ```

5. Type `soffice --version` and press Enter. Then type `exit`.
6. Optional: type `/usr/lib/libreoffice/program/soffice --headless --version`. It should print a version.

If `docker ps` shows nothing, ask Penny to do step 1 again, and check again straight after she finishes.

**Expected.**

- Penny says which PDF it made. Her answer names the file that office-convert wrote, such as live-test.pdf, and the file comes with a download card.
- Step 5: bash says that `soffice` was not found. The line ends in "command not found".
- Step 6 (optional): the program at its own path prints a version.

If step 5 finds `soffice`, run `docker inspect --format '{{.Created}}' <name>` and send its output with the result.

**Send back.** `D85: PASS`, or `D85: FAIL` with the words bash printed.

## 6. D105: Basil answers on the local model when Claude is limited (5 to 15 minutes, last)

**Why.** When Claude Code cannot answer, a member's chain moves to the next engine and says so. The local model is reached through an entry named `local-models`. Before the fix of 20 November 2026, a turn on a local model failed at the request: Ollama answered with an error, and the engine was marked unavailable (`docs/M1_PLAN.md`, section 67).

**Version.** 8b2fe79 or later. The fix is commit 9cde8e9, merged with pull request #404 (20 November 2026).

**Only if Claude is limited today.** This round cannot make Claude reach its limit. If Basil answers normally, this decision is not tested. Send `D105: not tested, Claude was not limited at <time>`.

**Once, before the test.** Edit your engines file, `openbot/agent-freeduet/engines.yaml`. It is your own copy of `engines.example.yaml`, and git does not track it.

1. The example keeps the `local-models` entry commented out. Uncomment it if it still is, set `enabled: true`, and set `model` to a model you pulled into Ollama. The comments in the example say how Ollama must listen so that the container can reach it.
2. Under `chains:`, Basil's line has the key `chef`. The example writes `chef: [claude-code, codex, local, openrouter]`. Change it to `chef: [claude-code, codex, local-models, openrouter]`. The entry `local` uses the OpenAI format, which only the light assistants use today (`docs/M1_PLAN.md`, section 66, decision D100), so it does not reach Basil.
3. From the repository root, run `bash scripts/start.sh`.

**Steps.**

1. In Basil's chat, write: `In three short lines, suggest a dinner with rice and eggs. Do not use any tool.`
2. Read the chat. If a line says that Claude Code reached its limit and that local-models is answering, the switch happened. Wait for the answer. The first answer may take several minutes while Ollama loads the model; this has not been timed yet. The proxy gives the local server up to 900 seconds (its read timeout) between bytes before it gives up.
3. Write down how many minutes the answer took.

**Expected.**

- The switch line, in English: "Claude Code reached its limit until <date> at <time> UTC, so local-models is answering instead." In Italian: "Claude Code ha raggiunto il limite fino al <data> alle <ora> UTC, quindi risponde local-models al suo posto." The "until" part is missing when the reset time is not known. The end of the line differs when Claude had already written part of its answer.
- Basil gives a short answer from the local model.
- No line says that no engine is available. In Italian that line starts "Ora nessun motore è disponibile."

**Send back.** `D105: PASS`, or `D105: FAIL` with the switch line word for word and the minutes the answer took.

## What this round does not test

- Full access. This round uses the default settings. D76 holds with Full access on as well, but this round does not check that.
- The mail path. D84 also changes which mail starts an email trigger. This round sends and receives no mail, so that rule is not tested (`docs/M1_PLAN.md`, section 63).
- A member that starts LibreOffice by its full path. The image takes the easy way away, not every way (`docs/M1_PLAN.md`, section 64).
- D105 while Claude answers, and any tool call on the local model.
- Accepting a routine. Only a refused one is tested (D81).
- Switching background research on (D80).
