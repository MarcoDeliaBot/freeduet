# FreeDuet v0.2.3: live test, round 2, engines

This is the checklist for one round of about 25 minutes on your own installation. It checks seven items of the Now table of `docs/ROADMAP.md` and the Next table (rows 119 and 120): the engine items of the ten-day sprint, step 2. Each item is built and tested in CI, and none has been run live: the ROADMAP rows say "not yet run live".

For each item the checklist gives the reason, the version you need, what to open, what to click, what you should see, a pass or fail box, and what to note if it fails. Each click is named as the app labels it. The labels come from the app code, and the file is named under each item. Run them in the order given. The slowest item (item 1) is the one most worth doing in full.

The decisions are recorded in `docs/M1_PLAN.md`, in the sections named below. v0.2.3 is not released yet. This round runs `main` at commit 5f006fe8 or a later commit.

## Before you start

1. **Check the version.** In the folder where FreeDuet is installed, run:

   ```bash
   git log -1 --oneline
   git merge-base --is-ancestor 5f006fe8 HEAD && echo "current enough"
   ```

   If the second command prints `current enough`, your copy includes commit 5f006fe8 (merged 25 November 2026, pull request #499). If it prints nothing or an error, update first.

2. **Update if needed.** FreeDuet must be running. From the folder of the installation, run `bash openbot/scripts/update.sh --main`. The script copies the database and `.env` first, moves the code to the newest `main`, starts FreeDuet again (which rebuilds the images), and checks that the app answers. If the app does not answer, it puts the old version and your data back. Wait until it prints `Updated.` or `Already up to date`, then run step 1 again.

3. **Open the Engines page.** Open the app, open Settings and choose "Engines". The page is for the administrator only (`openbot/app/src/routes/_authed/settings/index.tsx`). Its address is `/admin/engines`. Its title reads "Engines".

4. **Note your plan.** Write down whether your Claude plan is limited right now. Item 3 and item 6 may show it.

5. **Optional pre-check.** From the folder of the installation, run `bash openbot/scripts/freeduet-engines-precheck.sh`. It only reads: one OK, FAIL or SKIP line per check, and it changes nothing.

## Rules for this round

- Change an order or a choice only as a step names it, and undo it at the end of that step. Every change in this round is reversed before you go on.
- Switch on only the engine a step names (Ollama in item 3, if you have it). Switch off again what you switched on.
- Never type a key, a password or a token into the chat. Keys are typed only in the app's own form, and this round needs none.
- Press "Test" only where a step says so. A Test sends one real request to the provider.
- Send no mail. Make no payment and no purchase. Create no routine.
- If Iris offers a daily review, say no. It is not part of this round.

## 1. D112, D115, D116: engine order by hand (about 5 minutes)

**Why.** Each member's engines can be moved up and down, one place at a time (D112). An order that leaves the group order (your own logins, then free engines, then paid ones) is kept only after you tick and confirm it (D115). A free model that writes its tool call as text does not end the turn: the engine fails that turn and the next engine answers (D116). The same section of the page offers the OpenRouter model choice (`docs/M1_PLAN.md`, sections 73, 74 and 75).

**Version.** 5f006fe8 or later. D112 is commit 6b4361ab, D115 is commit 184275f7, D116 is commits 2ccbcebe and a282f55f (all on `main`).

**Open.** Settings, then "Engines". Find the table "Who uses what". Pick a member whose "Order of engines" column lists two or more engines that are switched on.

**Steps.**

1. Read the note above the table. It says that your own logins come first unless you choose otherwise.
2. On the first engine of that member's list, press the arrow whose name reads "Move <engine> down for <member>". Its name is in the accessible label, and the arrow has no text (`openbot/app/src/freeduet/engines-members.tsx`, `moveDownLabel` in `engines-text.ts`).
3. Look at the list. The two engines have swapped their numbers.
4. If a warning appears, read its title. It is one of two: "A free engine would answer before your own login", or "A paid engine would come before a free engine or a login". Press "Cancel". Do not tick the box.
5. Press "Undo the change for <member>" beside the row (the button "Undo"), or press "Use the recommended order" if the page shows it. The list goes back to its first order.
6. Optional, for D116: on the "Add an engine" page, find the OpenRouter card and open its model field. Read the choice "openrouter/free (OpenRouter picks a free model)" and the models of the list. Do not press "Save" (`openbot/app/src/freeduet/engines-providers-text.ts`, `FREE_ROUTER_LABEL`).

**Expected.**

- Step 2 and step 3: the two engines swap, and no card appears.
- Step 4: the warning shows the words of its title, and the buttons "I understand, use this order for <member>", "Confirm" and "Cancel". Nothing is written until you tick and press "Confirm".
- Step 5: the order is back, and the page shows no note "Your order: logins are not first".
- Step 6 (optional): the choice and the list show. Nothing is saved.
- D116 has no button to press. If a member's last answer shows under an engine "Its last answer wrote its tool calls as text instead of using them: choose a model that supports tools", write it down: it is D116 working. Do not try to make it happen.

**Result.** [ ] PASS   [ ] FAIL   [ ] not tested

**If it fails, note:** the warning's words, whether a move changed the order without a tick, and whether Undo restored it.

**Send back.** `D112, D115, D116: PASS`, or `FAIL` with the warning's words, or `not tested, one engine only` if the member had one engine on.

## 2. D113: the FreeLLMAPI card is off, with its warnings (about 3 minutes)

**Why.** An optional card points a member's engine at a FreeLLMAPI router that you run on your own computer. FreeDuet ships none of its code. Data sent to the router passes on to the providers behind it, and a FreeLLMAPI engine is never first in a chain (`docs/M1_PLAN.md`, section 73, D113).

**Version.** 5f006fe8 or later. The card came in with commit e555328e (21 November 2026, pull request #426).

**Open.** Settings, then "Engines", then the section "Add an engine".

**Steps.**

1. Find the card "FreeLLMAPI (router on your computer)". Its tag reads "Advanced: your own router" (`openbot/app/src/freeduet/engines-providers-text.ts`, `PROVIDER_TEXT` and `TAG_TEXT`).
2. Read the card's advanced note, the warning under the card, and the address note. Do not press "Save".
3. Leave the switch "Switch on FreeLLMAPI (router on your computer)" off.
4. Optional: only if you run a FreeLLMAPI router yourself on your computer, write its address in the "Server address" field and press "Load list". FreeDuet does not install the router. Do not paste a key anywhere. Then clear the field again.

**Expected.**

- The card is off, and the tag reads "Advanced: your own router".
- The advanced note starts with "Advanced option, not a recommended default".
- The warning reads "Your messages go to the router, which passes them on to the free providers you enabled inside it."
- The address note says that the router's own default port, 3001, is FreeDuet's, so the router runs on another port.
- Step 4 (optional): the list loads, or the page says what is missing.

**Result.** [ ] PASS   [ ] FAIL   [ ] not tested

**If it fails, note:** what the card showed, and whether the advanced note or the warning was missing.

**Send back.** `D113: PASS`, or `FAIL` with what the card showed, or `not tested, no router of your own` (the card's look is still checked by steps 1 to 3).

## 3. D109: engines are added in three clicks (about 4 minutes)

**Why.** Each provider has one card with a switch, an address, a model field with "Load list", a key field with "Save", and a "Test" button. A cloud provider's card warns that data leaves your computer. The key is kept on this installation and is not shown again after Save (`docs/M1_PLAN.md`, section 71, D109).

**Version.** 5f006fe8 or later. D109 is commit ada50317 (merged as #414 on 20 November 2026).

**Open.** Settings, then "Engines", then "Add an engine".

**Steps.**

1. Find the card "Ollama" with the tag "Local" and the text "Models that run on your own computer." Read the card. Its switch reads "Switch on Ollama".
2. Find the card "Groq" with the warning "Data sent to this service leaves your computer." Read the card, the field "Key" and its placeholder "Paste the key here". Do not switch it on and do not type a key.
3. Optional: if Ollama runs on your computer, switch "Switch on Ollama" on, press "Load list", press "Test", then switch it off again. "Test" sends one request to Ollama on your own computer. Nothing leaves the computer and nothing is billed.

**Expected.**

- Step 1: the card shows the Local tag and the switch. Switched on, it takes its address and model from its fields (`openbot/app/src/freeduet/engines-providers.tsx`, the switch's label "Switch on <name>").
- Step 2: the card shows the cloud warning, and the key field is empty.
- Step 3 (optional): "Load list" shows the models Ollama has, and "Test" reports that the engine answered. Switched off again, the card is as it was.

**Not done in this round.** Pasting a key and pressing "Save" on a cloud card: it needs your own key, and you type it in the app's form, never in the chat. Mark it "not tested, optional" if you do not do it.

**Result.** [ ] PASS   [ ] FAIL   [ ] not tested

**If it fails, note:** the card's words, and whether the switch, Load list or Test behaved as written.

**Send back.** `D109: PASS`, or `FAIL` with the card's words, or `not tested` with the reason (the Ollama step is optional).

## 4. D102 and D126: the token counter (about 3 minutes)

**Why.** Each member's tokens are counted per engine and per day, as each engine reports them, next to the plan's limit when it is known. The page also shows a saved line for tokens that free or local engines handled, and what they would have cost on one declared paid model, in euros or dollars (`docs/M1_PLAN.md`, section 84, D102 and D126).

**Version.** 5f006fe8 or later. D102 is commit 1071c949, and the Tokens section with D126 is commit f4c9380a (merged as PR #441 on 21 November 2026).

**Open.** Settings, then "Engines", then scroll to the section titled "Tokens".

**Steps.**

1. Read the description under "Tokens": "What each member used on each engine, as the engine itself reported it. Days are counted in UTC."
2. Read the table's columns: "Member", "Engine", "Today" and "Last 7 days". The first row of the table is "All members".
3. Read the section "Plan limits", if it shows.
4. Click an amount in the table. It switches between euros and dollars (`openbot/app/src/freeduet/engines-tokens-text.ts`, `CURRENCY_HELP`: "Click an amount to switch between euros and dollars.").
5. Read the line below the table, and its small reference line.

**Expected.**

- Step 1 and step 2: the description and the four column titles match the words above.
- Step 3: either "No engine is held back by a limit right now." or the page's limit line. The page never shows a percentage of your weekly limit: the subscription does not report one.
- Step 4: the amounts change between euros and dollars.
- Step 5: the reference line reads like "At Claude Sonnet 5.5 list prices ($2 in, $10 out per million tokens, 21 Nov 2026); €1 = $1.0989 (17 Nov 2026)." The price is a fixed list price with its date, not a fetched one.
- If no turn has been counted yet, the page says "No turn has been counted yet." That is a result: write it down and go on.
- A cell that an engine did not report reads "not reported", and does not read zero.

**Optional.** Send Iris one line: `Reply with the word ok.` Then reload the page. Today's count for her Claude Code engine should be higher than before. That uses your Claude plan for one short turn.

**Result.** [ ] PASS   [ ] FAIL   [ ] not tested

**If it fails, note:** what the table or the line showed, and whether the amounts changed between euros and dollars.

**Send back.** `D102, D126: PASS`, or `FAIL` with what the table or the line showed.

## 5. D110, D120: Rex, the model trainer, answers and changes nothing (about 4 minutes)

**Why.** Rex tests the models a person can use and recommends which engine fits which member. He never changes an engine: he proposes, and you decide on the Engines page. He never spends money, and an eval run that uses your Claude plan starts only after your yes. He works from what you paste, because he has no tool that reads the Engines page (`docs/M1_PLAN.md`, sections 72 and 78, and the ROADMAP row "Rex, the model trainer").

**Version.** 5f006fe8 or later. Rex came in with pull request #427 (commit 60dc590d), on 21 November 2026.

**Open.** Settings, then "Bots", then open Rex (title "Model trainer"). Start a chat with Rex.

**Steps.**

1. Open the Engines page in a second tab and copy only the engine names of one member's "Order of engines" column (not any key or address). Paste them into your chat with Rex.
2. Write to Rex: `Which engine in this list fits Basil best, and why? Work from what I pasted. Run no test and change no engine.`
3. Read his answer.
4. If he offers to run an eval, write: `No, not now.`

**Expected.**

- Rex answers from the list you pasted. He says that he cannot read the Engines page, or that he works from what you paste. He does not claim that a test ran.
- No card asks you to change an engine, and no card asks for a key.
- Step 4: he drops the eval run and does not start it.

**Fail if.** He changes an engine, asks you to type a key into the chat, claims to have run a test, or starts an eval run after you said no.

**Result.** [ ] PASS   [ ] FAIL   [ ] not tested

**If it fails, note:** Rex's words, and any change, card or key request that followed.

**Send back.** `D110, D120: PASS`, or `FAIL` with his answer's first line, or `not tested, no Rex in your team`.

## 6. D139: the engine and effort per member (about 3 minutes)

**Why.** Each member whose engines include Claude Code gets two choices: which Claude model (Haiku, Sonnet or Opus) and how much effort (low to max). Nothing chosen means the subscription's default. A model your plan cannot use ends that turn with the CLI's own error, and switches nothing off (`docs/M1_PLAN.md`, section 95, D139).

**Version.** 5f006fe8 or later. D139 came in with commits 744763b5 and a1185934 (on `main`).

**Open.** Settings, then "Engines", then the table "Who uses what". Find a member whose "Order of engines" column includes "Claude Code".

**Steps.**

1. Find the select "Claude model for <member>" beside Claude Code. Its options read "Subscription default", "Haiku", "Sonnet" and "Opus" (`openbot/app/src/freeduet/engines-text.ts`, `CLAUDE_MODEL_OPTIONS`).
2. Choose "Haiku".
3. Find the select "Claude effort for <member>". Its options read "Subscription default", "Low", "Medium", "High", "Extra high" and "Max". Choose "Low".
4. Read the note under the choices.
5. Choose "Subscription default" in both selects. This undoes the choice.

**Expected.**

- Steps 2 and 3: "Claude choice saved. It applies from the next message." shows each time.
- Step 4: the note reads "Claude Code only. A model your subscription cannot use ends that turn with Claude Code's own error. Nothing is switched off, and Subscription default undoes the choice."
- Step 5: the saved line shows again, and the selects read "Subscription default".
- A member without Claude Code in its list shows no selects. That is also a result.

**Optional.** After step 2, send that member one short line: `Reply with the word ok.` Then reset to "Subscription default". Any error text Claude Code gives is written down with the result.

**Result.** [ ] PASS   [ ] FAIL   [ ] not tested

**If it fails, note:** the page's words, and whether the choice stayed after a reload.

**Send back.** `D139: PASS`, or `FAIL` with the page's words, or `not tested, no member with Claude Code`.

## 7. Row 120: the Week view of the routines (about 3 minutes)

**Why.** The Routines page has a Week view beside the list: the current week, Monday first, hours down the side, one block for each run. It is read-only and changes nothing about how a routine runs (`docs/M1_PLAN.md`, section 96, D140). The ROADMAP row says the look waits for your yes, so this step checks what your installation shows, and it does not decide the look.

**Version.** 5f006fe8 or later. The view came in with commit fd173900 (merged with pull request #458).

**Open.** Settings, then "Routines" (the page's address is `/routines`).

**Steps.**

1. Read the views on the page: "Routines", "Week", "Next runs" and "History" (`openbot/app/src/components/routines/routines-list.tsx`).
2. Press "Week".
3. Read the grid. If a routine exists, find its block. If none exists, read the empty state.
4. Read the footer under the grid.
5. Press "Routines" to go back. Then reload the page and press "Week" again to see whether the choice is remembered.

**Expected.**

- Step 2: a grid of the current week, Monday first, with the hours down the side (`openbot/app/src/components/routines/routine-week.tsx`).
- Step 3: each routine is a block at the time it runs. With no routine, the page says "No routines yet, so nothing is scheduled."
- Step 4: the footer shows "Next: " and the next run, or nothing if no run is coming.
- Step 5: the choice is remembered in this browser only.

**Do not.** Create, change or delete a routine in this step. Routines are set up in the chat, and that flow is round 1's item 4.

**Result.** [ ] PASS   [ ] FAIL   [ ] not tested

**If it fails, note:** what the grid or the footer showed, and whether the Week button was there.

**Send back.** `D140 (row 120): PASS`, or `FAIL` with what the grid showed, or `not on this installation` if the "Week" button is missing.

## What this round does not test

- Any real order change that a member uses on a turn. Item 1 undoes every move.
- A paid engine. No paid engine is switched on in this round.
- A key typed into a cloud card (item 3). It needs your own key, and it is typed in the app's form.
- The FreeLLMAPI router itself (item 2), and the look of the cards in your browser.
- The D116 fallback on demand: it happens only when a free model writes a tool call as text.
- Eval runs of Rex, which use your Claude plan and need your yes.
- The look of the Week view, which waits for the maintainer's yes (ROADMAP row 120).
- Any change to a routine.
